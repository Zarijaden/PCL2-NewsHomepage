#### 硫方怪

- 加入了硫方怪生物
- 生成于新的硫黄洞穴生物群系
- 当玩家手持方块与其交互时：
  - 硫方怪会吸收该方块
  - 其 AI 被禁用
  - 当吸收了一个方块后：
    - 硫方怪变成一个物理对象：
      - 不会受到摔落伤害或玩家攻击伤害
      - 玩家可以拳击并推动它
    - 它会根据吸收的方块，采用一种原型（见下文），改变其物理属性以匹配该方块
    - 玩家可以使用剪刀与其交互：
      - 这会移除被吸收的方块
      - 硫方怪的 AI 重新启用
- 硫方怪会跟随手持可吸收方块的玩家
- 硫方怪会寻找附近的方块物品并移向它们以进行吸收
- 被杀死时，硫方怪会分裂成两个较小的硫方怪
- 小硫方怪可以通过喂食黏液球成长为大型硫方怪
- 大型硫方怪可以使用空的铁桶装起
- 硫方怪不能进入船，但可以乘坐矿车
- 发射器可以：
  - 向硫方怪内部放入或交换方块
  - 使用剪刀移除其持有的方块
  - 从硫方怪桶中生成一个硫方怪
- 河豚不会被硫方怪吓到

# 硫方怪原型

- 每种原型由硫方怪被击中时的速度、与方块和可碰撞实体碰撞时的弹性，以及地面摩擦力、空气阻力和是否在液体中漂浮来定义。
- 有以下原型：
  - 普通：中等速度，中等弹性，中等地面摩擦力，低空气阻力
    - 可漂浮
    - 用于吸收松散矿物和土壤类方块
  - 弹性：快速，高弹性，中等地面摩擦力，低空气阻力
    - 可漂浮
    - 用于吸收木质方块
  - 缓慢弹性：慢速，高弹性，中等地面摩擦力，中等空气阻力
    - 用于吸收类石方块
  - 缓慢平移：慢速，低弹性，中等地面摩擦力，中等空气阻力
    - 用于吸收金属类方块
  - 快速平移：快速，低弹性，中等地面摩擦力，低空气阻力
    - 用于吸收有机类方块
  - 轻盈：慢速，高弹性，中等地面摩擦力，高空气阻力
    - 可漂浮
    - 用于吸收羊毛方块
  - 快速滑行：快速，无弹性，低地面摩擦力，低空气阻力
    - 用于吸收冰类方块
  - 缓慢滑行：慢速，无弹性，低地面摩擦力，低空气阻力
    - 用于吸收菌类方块
- 还有以下特殊原型：
  - 高阻力：极慢，低阻力，低弹性，高摩擦力
    - 用于吸收灵魂沙和灵魂土
  - 黏性：属性与快平板原型相同，但具有极高的地面摩擦力且无弹性以模拟粘性
    - 用于吸收蜜脾块
  - 爆炸：属性与常规原型相似，但空气阻力略高
    - 用于吸收 TNT 方块
    - 吸收的 TNT 可以通过红石、火源（包括装有打火石的发射器）或附近的爆炸点燃
    - 被火或红石点燃时，吸收的 TNT 使用 6 秒的引信时间
    - 被爆炸点燃时，吸收的 TNT 使用 0.75 到 3 秒之间的随机引信时间
    - 吸收了已点燃 TNT 的硫方怪无法用桶装起
    - 已点燃的 TNT 无法用剪刀剪出
    - 爆炸时不会生成小硫方怪
  - 高温：属性与常规原型相同，但接触时会伤害实体
    - 用于吸收岩浆块

#### 烈性硫黄

- 是一种在硫黄洞穴生物群系的水池中自然生成的新方块
- 会产生气泡，气泡可上升至其上方 4 格水源方块
- 当放置在最多为 4 格水源方块下方时，会在水面上产生一片引发反胃效果的气体云
- 这片气云会扩散到相邻的水域，最大半径为 3 格
- 可以由 9 个硫黄方块合成
- 当放置在岩浆块或熔岩上方，且上方有 1-4 格水源方块时，会形成间歇泉
  - 下方为岩浆块时，间歇泉会以随机间隔喷发，向上喷射水粒子柱，并对上方的实体施加向上的冲量
  - 下方为熔岩时，间歇泉会持续喷发，但声音相比岩浆块喷发略微减弱
- 间歇泉喷发会在喷发开始和结束时发出游戏事件，可被幽匿感测体检测到

#### 硫黄尖锥

- 是一种在硫黄洞穴生物群系的硫黄方块上自然生成的新方块
- 放置在顶部时形成钟乳石，放置在地面时形成石笋
- 可以组合形成更长的钟乳石和石笋
- 如果尖端相邻，钟乳石和石笋会合并，除非你在放置时潜行
- 硫黄尖锥钟乳石在放置在硫黄方块下方时可以生长
- 石笋如果没有连接到下方的方块则会断裂
- 钟乳石如果没有连接到上方的方块则会掉落
- 被掉落的钟乳石击中会造成伤害——因为它们很锋利！
- 石笋不锋利，落在上面不会造成更多伤害
- 投掷的三叉戟会破坏硫黄尖锥
- 四个硫黄尖锥可以合成一个硫黄

#### Vulkan 支持

- 正如[之前宣布](https://www.minecraft.net/article/another-step-towards-vibrant-visuals-for-java-edition)的那样，我们打算将游戏从 OpenGL 切换至 Vulkan
- Vulkan 不支持较旧的硬件或驱动程序
- 在这些情况下将使用 OpenGL 作为后备
- 当前要求是 Vulkan 1.2，支持动态渲染和推送描述符，但此要求可能会随时间变化
- 这目前是一个实验性渲染后端，性能和稳定性可能不如预期
- 如果你发现任何 Bug，请报告至[我们的 Bug 追踪器](https://report.bugs.mojang.com)
- 在 Vulkan 下，我们会优先使用你的独立显卡而非集成显卡，这与 OpenGL 下的行为不同
- 你可以在 F3 调试覆盖层中查看正在使用的后端（位于 system_specs 部分）
- 在 macOS 上，我们使用 MoltenVK 将 Vulkan 转换为 Metal

#### “图形 API”视频设置

- 这是“视频设置”中的一个新选项
- 有三个值：默认、优先 Vulkan（实验性）和优先 OpenGL
- “默认”可能会由我们自行更改，我们建议所有用户使用此选项，除非你遇到问题需要更改
- 目前，它与“优先 OpenGL”相同
- “优先 Vulkan（实验性）”会尝试使用 Vulkan 渲染，但如果无法工作则回退到 OpenGL
- Vulkan 支持目前是实验性的，使用它可能会降低性能或在某些系统上导致不稳定
- “优先 OpenGL”会尝试使用 OpenGL 渲染，但如果无法工作则回退到 Vulkan

##### 启动与回退行为

- 如果在设置为“优先 Vulkan（实验性）”时游戏在启动时崩溃，该设置将自动改为“默认”
- 当设置为“默认”时，游戏仍会在启动时尝试收集 Vulkan 的系统信息
- 如果在设置为“默认”时游戏在启动时崩溃，该设置将自动改为“优先 OpenGL”
- 设置为“优先 OpenGL”时，不会与 Vulkan 进行任何交互，以防导致崩溃

### 技术性更改

- 数据包版本现为 `107.1`

- `particle_render_stats` 现在包含不同粒子组的计数（SQ 为单四边形，NR 为不渲染，EG 为远古守卫者，IP 为物品拾取）以及总数
- 如果玩家没有该目标，玩家的分数将不再显示在玩家列表覆盖层中
- 遥测数据更新

#### 服务器属性

- 加入了 `chat-spam-threshold-seconds` 和 `command-spam-threshold-seconds` 属性，将聊天和命令的 spam 阈值分开
- 两个阈值默认均为 10，这是之前命令+聊天组合 spam 的现有阈值
- 这些阈值配置了自动踢出发送过多聊天消息或命令的玩家的机制
- 该值描述了玩家必须发送多少秒的 spam 才会被踢出，其中玩家每发送一条消息，计数器增加 1 秒
- 计数器每 tick（相当于 1/20 秒）递减一次，当计数器达到配置的阈值时，玩家被踢出
- 任一阈值均可设置为 0 以禁用对应类型的 spam 踢出
- 在默认阈值 10 下，会导致踢出的消息速率示例：
  - 1 秒内发送 11 条消息
  - 2 秒内发送 14 条消息
  - 10 秒内发送 21 条消息

#### Minecraft 服务器管理协议 3.0.0

- 管理服务器现在在 Minecraft 服务器启动之前启动
- 最主要的影响是，心跳现在会在世界加载和可能升级时发送
- `rpc.discover` 和 `notification/server/status` 方法现在可以在专用服务器启动之前访问
- 在此期间调用其他方法时，服务器将返回错误

#### 遥测

##### 世界事件中的新属性

- `server_session_id`：多人游戏会话的唯一标识符，该会话中的所有玩家共享
- “会话”定义为至少有一名玩家在服务器中的连续时间段
- 此属性是必需的，不受选择加入设置的影响

##### 新的必需事件

- `graphics_capabilities`：这是一个在启动时发布的新事件，报告用于游戏的图形设备的能力
- 新增属性 `backend_name`：将为 Vulkan 或 OpenGL，帮助我们了解玩家正在使用哪种图形 API
- 新增属性 `backend_failure_reason`：将为简短错误代码列表，例如 `vulkan_device_version_too_low`，帮助我们识别针对 Vulkan 要求的任何问题
- 新增属性 `backend_failure_message`：将为简短而模糊的消息，例如 `Failed to find the GLFW platform surface extensions`，帮助我们在玩家使用 Vulkan 遇到问题时缩小范围
- 新增属性 `backend_failure_missing_capabilities`：将为缺失的 Vulkan 能力列表，例如 `VULKAN_CORE_1_2`、`VK_KHR_dynamic_rendering`，帮助我们了解玩家使用 Vulkan 所需的能力


### 数据包版本 107.1

#### 硫方怪原型注册表

- 添加了数据驱动的 `minecraft:sulfur_cube_archetype` 注册表。元素从 `data/<namespace>/sulfur_cube_archetype/<path>.json` 加载。
- 条目格式：包含以下字段的对象：
  - `items`：物品标签，包含可以喂给此原型硫方怪的所有物品
  - `buoyant`：布尔值，指示此原型的硫方怪是否在液体中漂浮
  - `explosion`：可选字段，如果存在，此原型的硫方怪会爆炸：
    - `fuse`：正整数，点燃时的引信时间
    - `power`：非负整数，爆炸威力
    - `causes_fire`：布尔值，爆炸是否引发火灾

##### 实体谓词

实体谓词格式已从带有多个可选字段的结构更改为类似于数据组件映射的结构。例如：

- 之前，`effects` 是一个可选字段：`{ "effects": {...} }`
- 在此版本中，它已成为一个类似组件的子谓词条目：`{ "minecraft:effects": {...} }`

主要功能变化：

- 实体谓词中的所有键现在都是命名空间 ID
- 由于命名空间 ID 可以不写命名空间（默认为 `minecraft` 命名空间），现有字段名称仍然有效
- 例外：字段 `type` 已重命名为 `minecraft:entity_type`
- 无法识别的子谓词组件现在会被拒绝（之前未知字段会被忽略）

现有的类型特定子谓词已重命名并移至顶层：

- `minecraft:lightning` → `minecraft:type_specific/lightning`
- `minecraft:fishing_hook` → `minecraft:type_specific/fishing_hook`
- `minecraft:player` → `minecraft:type_specific/player`
- `minecraft:raider` → `minecraft:type_specific/raider`
- `minecraft:sheep` → `minecraft:type_specific/sheep`
- `minecraft:slime` → `minecraft:type_specific/cube_mob`（现在除了史莱姆和岩浆怪外，还包括硫方怪）

例如：

```json
{
  "type_specific": {
    "type": "minecraft:player",
    "looking_at": {
      "type": "minecraft:ender_dragon"
    }
  }
}
```

变为：

```json
{
  "minecraft:type_specific/player": {
    "looking_at": {
      "minecraft:type": "minecraft:ender_dragon"
    }
  }
}
```
